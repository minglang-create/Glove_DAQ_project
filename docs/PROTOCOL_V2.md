## 0. 评审决议(已获批, 落入本规格)
1. XVS 驱动**开漏+上拉**; STM32 进主机流程前先采样 XVS, 已被拉低→自动转从机(+ms级随机退避)。
2. **固定长度全双工事务**(见 §1), CAN 发送包暂不实现(未来灵巧手, 帧头 0xFD01 保留)。
3. **XVS 自检后常开不停**; 开采/停采只控制"是否记录/是否装载数据包"。段号 SEG 由
   开采包携带、RV 本地跟踪, **数据包不回带**(暂停=停采包后 STM32 不再装载数据包/
   不拉 PA1, XVS 继续发, 相机锁相不中断)。
4. PA1(DATA_READY) → RV **GPIO0_A4**(SoM 球 K13, 默认下拉); 软件默认 -g 0:4。
5. 姿态回归**四元数 4×int16 Q14**; 心跳位图两包统一; CYCLE 暂停后续计不清零。
6. ★2026-09-02★ **启停本地对称**: 每只手套的 RV 读【自己的按键】、发 0xC101/0xC201
   给【自己的 STM32】——从机不再推断主机的启停(无可靠通道)。XVS 常开是共享时基,
   两侧启停早晚无所谓, 后处理按 CYCLE 对齐裁剪。主从之分只决定"谁驱动 XVS"。
7. XVS 波形定稿: 60.000Hz, 低有效, 标称低宽 10µs(合法范围≈1~2H, 1H=7.242µs@当前D档);
   ★下降沿=帧基准★(XVSLNG 脉宽可配 1/2/4/8H 而不影响定时 → 基准只能是下降沿;
   STM32 自己计数用哪个沿随意, 恒差一个脉宽)。

## 1. 事务模型(最重要的一节)
- RV 是 SPI 主机, Mode0 / MSB / 8bit / CS 整事务不抬; SCK 首跑 5MHz。
- **每次事务固定 1345 words(2690 字节)全双工**(=数据包长; 长度永不切换,
  "CTRL/DATA"只是内容之分不是长度之分 → 失步问题从根上消失):
  - MOSI: 主→从包放 word0 起, 其余填 0x0000。无包可发 = 全 0(NOP)。
  - MISO: 从→主包放 word0 起(小包或数据包)。**无包 = 全 0**(帧头 0x0000 不属于任何包)。
- STM32 语义: 事务完成(CS 升沿)= 包被取走 → 重装下一包; 重复读同包合法。
- ★硬约束: 相邻两次 SPI 事务之间必须留 **≥100µs** 间隔(STM32 重装 DMA 的窗口),
  背靠背连读会读到未装载的垃圾。RV 侧 glove_link.c 已在 spi_txn() 强制执行。★
- PA1: 高 = MISO 有包就绪(运行态=数据包; 其它状态=有小包时也建议拉高, RV 侧兼容
  "PA1 沿触发 + 100ms 轮询兜底"两种节奏)。
  ★时序(2026-09-02 STM32 侧实测修正): PA1 在 XVS 后 **3~8ms** 拉高(固件要等
  CAN 回帧窗 ~2.5ms 与 IMU 批量读, 内部超时上限 8ms), 保持到下个 XVS。
  RV 读窗口 = 最差 8.6ms(仍 ≫ 4.3ms 事务), 超时判据不得按 100µs 设。★
- 解析规则统一: **读满 2690 字节 → 看 word0 帧头分流**(0x0000=无包/小包表/0x6A01=数据包)。
- LENGTH 字段统一语义: **不含帧头、不含自身、含 CRC 的 word 数**。
  小包 = 4(0x0004); 数据包 = 1343(0x053F)。
- CRC-16/IBM = CRC-16/ARC: poly 0x8005(反射 0xA001), init 0x0000, 无终异或,
  按**字节流**计算(即线上顺序), 覆盖 帧头..CRC 前一字节。自检向量: CRC("123456789")=0xBB3D。
  CRC 值按大端放进最后一个 word。

## 2. 小包(全部 6 words = 12 字节)
布局: w0=帧头, w1=LENGTH(0x0004), w2..w4=数据 3w, w5=CRC(覆盖字节 0..9)。
事务载体: 小包置于整帧长缓冲头 6 words, 其余全 0。MOSI 前 6 words **任何时候**可携带
控制包(停采可搭在读帧事务里); CAN 发送包将来同样装进固定事务(内部限条数)。

| 帧头 | 名称 | 方向 | 数据 w2/w3/w4 |
|---|---|---|---|
| 0xAA01 | 通信测试包 | 从→主 | 0xFFFF / 0xFFFF / 0xFFFF |
| 0x5101 | 是主机 | 主→从 | 0xFFFF ×3 |
| 0x5201 | 是从机 | 从→主 | 0xFFFF ×3 |
| 0x5301 | 收到(握手确认) | 双向 | 0xFFFF ×3 |
| 0x5401 | STM32 自检包 | 从→主 | 心跳位图 u32(高w在前) / 特殊状态 1w |
| 0x5501 | RV 自检完成 | 主→从 | 0xFFFF ×3 |
| 0x5F01 | 重新自检 | 主→从 | 0xFFFF ×3 |
| 0xC101 | 开采 | 主→从 | **SEG 段号** / 0xFFFF / 0xFFFF |
| 0xC201 | 停采 | 主→从 | 0xFFFF ×3 |
| 0xE101 | LED 标定 | 主→从 | 亮灯 cycle 数(默认1) / 0xFFFF / 0xFFFF |
| 0xE201 | 版本查询 | 主→从 | 0xFFFF ×3 |
| 0xE301 | 版本应答 | 从→主 | 协议版本(=1, 即帧头低字节; "v2"只是文档修订号) / 固件主版本 / 固件次版本 |
| 0xFD01 | CAN 发送 | 主→从 | ★保留未实现★ |

版本查询(0xE201)只在**非运行态**发起: 运行态 MISO 被数据帧占用, STM32 收到即忽略。
LED 标定(0xE101)★暂缓★: V4 硬件已无 MCU 可控 LED(原 LED 脚在排针上且其一连着
XVS 网——那个脚禁止接 LED, 会加载时基网)。分析结论(2026-09-02): CYCLE 在数据包内
自带、PA1 锚定的整数指派唯一(见 §7), LED 标定要解决的问题基本不存在, 保留帧头备用。

## 3. 数据包(0x6A01, 1345 words = 2690 字节)★2026-09-01 用户定稿重写★
| word | 字节 | 长(w) | 字段 | 说明 |
|---|---|---|---|---|
| 0 | 0 | 1 | MAGIC | 0x6A01 |
| 1 | 2 | 1 | LENGTH | 0x053F = 1343(不含帧头/自身, 含 CRC) |
| 2 | 4 | 2 | CYCLE | u32, XVS 计数, 首脉冲=1, **暂停不清零** |
| 4 | 8 | 2 | HEARTBEAT | u32, 位图见 §4 |
| 6 | 12 | 40 | JOINT[20] | 各 u32: bit[22:0]=角度, bit[31:23]保留; 0xFFFFFFFF=缺失 |
| 46 | 92 | 5 | TAC_STAT[5] | 每片状态字 |
| 51 | 102 | 1280 | TACTILE[5][16][16] | uint16 行优先 |
| 1331 | 2662 | 6 | IMU_RAW | int16 ×6: ax ay az gx gy gz |

## 4. 心跳位图(自检包与数据帧**同布局同极性**, 2026-09-02 修正)
bit=1 表示该节点无数据/异常; bit0..19=关节1..20, bit20..24=触觉1..5,
bit25=IMU, bit26=磁力计, bit27=TYPE-C PD。
两包差异只在高位段:
- **数据帧**: bit27~31 保留恒 1(PD 位在数据帧无意义, 随保留段恒1);
- **自检包**: bit27=1 表示 PD 高压缺失(有效位), bit28~31 恒 0。

## 5. 状态机与包时序(摘要, 细节见 frame_note)
自检(STM32 预装通信测试包→自检包) → 主从分配(按键→0x5101 / XVS 先到→0x5201, 均以
0x5301 收尾) → 主机 XVS: 拉低 2s(仲裁窗+从机相机启动) → 60Hz **此后常开** →
双方相机自检 → RV 发 0x5501 → 就绪 → **启停(两侧对称)**: 各手套 RV 读自己的按键,
发 0xC101(带 SEG)/0xC201 给自己的 STM32; STM32 据此开始/停止装载数据包与拉 PA1
(XVS 全程不停) → 长按结束。
两侧启停时刻互不通知、允许错开: CYCLE 是共享时基, 后处理按 CYCLE 交集对齐裁剪。
注意: SEG 段号只在【本手套】内有意义(两侧独立计), 跨手套对齐一律用 CYCLE。

## 6. 自检假数据模式(-V 验收, STM32 自检固件按此造数)
TACTILE 第 k 字(k=0..1279)= 自身字下标 = 51+k(51..1330);
JOINT[i] = ((CYCLE & 0xFFF) + (i<<12)) & 0x7FFFFF; TAC_STAT[i] = 0xA500|i;
QUAT = {16384, 变化, 0, 0}; IMU_RAW[i] = 1000+i; MAG_RAW[i] = 2000+i;
HEARTBEAT: 关节0~3 与 IMU 位=0, 另一位随 CYCLE 轮转。

## 7. 相机帧↔CYCLE 对齐(为何不再需要 LED 标定, 2026-09-02)
- CYCLE 由数据包自带, 无需从时间恢复; 唯一要定的是"相机 PTS 网格 ↔ XVS 网格"的映射。
- 锚点 = PA1 上升沿的内核时间戳(RV 侧 t_edge_ns)。PA1 相对 XVS 有 3~8ms 抖动,
  但多帧取中位数后锚点系统误差 ≤±2.5ms, 远小于半周期 8.3ms → 最近邻整数指派**唯一**。
- 交叉验证: XVS→相机 SOF 的常数可由传感器时序解析算出(从机触发后固定行数开始读出);
  上板后看对齐残差分布, 单峰且 σ<1ms 即证明指派稳定。
- 脉宽标记(XVS 加宽脉冲)相机不可见(边沿触发), 不能做"视频内容级"标定——但由上述
  两条, 视频内容级标定不再必要。0xE101 保留不删, 万一将来要用。
