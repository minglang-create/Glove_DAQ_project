# 简化启动方案(2026-09-04 定稿, 分支 cam-xvs-simple-start)

> ★2026-09-04 实测通过★ 全链路同时跑: 手套 60Hz 零错 + 双摄 60fps(dpts -5~-6µs)
> + 对齐引擎锁定(offset=-3.90ms, σ=173µs, n>1000)。

> 取代《协议契约_V1 第四次修订》中的启动流程部分(§6 XVS 线、§7 全流程);
> 事务模型、小包表、数据帧布局、CRC 等其余部分**不变**。

## 为什么改

实验 B(2026-09-04)实锤:**IMX415 从机启动必须同时收到 XVS+XHS**,而 V4 板的
XHS 网只在两颗相机间互连、没接 STM32 → "STM32 供 XVS 驱动双从相机"此板走不通。
解法 = XVS 源移回相机:**cam0 当主机自产 XVS+XHS**(本手套内 cam1 直接锁,
V2/V3 已验证 dpts 恒 −6µs),**STM32 从"发 XVS"改为"捕获 XVS"**——
TXS0101 双向电平转换自动转向,硬件一根线不用动。

顺带把主从分配砍到最简:**主机不等从机、不设应答窗**;主/从机是否都在工作,
由工人根据两只手套的 LED 灯光自行判断。

## 新启动流程

```
双方上电 → 各自自检(RV: 相机在位+SD; STM32: CAN/IMU) → RV 发 0x5501
  → STM32 自检完 + 收到 0x5501 → LED 亮(等按键)
工人按【任一只】手套按键(全流程唯一一次按键)
  → 该侧 RV 发 0x5101"是主机"
  → 该侧 STM32: ①拉低 XVS 50ms(向对侧手套宣告"我是主机")→ 释放
               ②PB10 切 TIM2_CH3 输入捕获(下降沿, 从此只听不说)
               ③发 0xC301"请求采集"(P0=1)给自己的 RV
  → RV 收 0xC301 → 启动相机(hwsync: cam1 从机先武装, cam0 主机后起振,
     ★cam0 起振即向全系统持续输出 XVS+XHS★) → 回 0xC101
  → STM32 捕获到第一个 XVS 下降沿 = CYCLE 1 → 逐拍采集/装数据帧/拉 PA1
  → RV 读到第一个数据帧 = RUNNING(开录像段)
对侧手套(从机, 无按键): STM32 检测 XVS 持续低 >30ms(运行中低脉宽仅 7.2µs,
  不会误判)→ 自判从机 → 装 0x5201 → 发 0xC301(P0=2)给自己的 RV → …
  ⚠ 双手场景本分支未闭环(见"已知边界")
按键(2026-09-07 定稿): 空闲短按=开采(0x5101); 任何时候【长按≥2s】= 段收口+fsync → 发 0x5F01
  (STM32 回自检, XVS/相机停)→ RV exec 重启回待机 → 再短按=重新开采(新段)。
  不用 0xC201/0xC101 暂停恢复(STM32 侧逻辑保留, RV 不再使用)。采集中短按忽略(防误触)。
  按键永不退出程序; 没有"结束"键——真要结束就长按看到"数据已落盘 ✓"后断电。
```

## 关键参数变化

| 项 | 旧(STM32 供 XVS) | 新(cam0 供 XVS) |
|---|---|---|
| XVS 源 | STM32 PB10 定时器输出 | cam0(IMX415 internal master) |
| XVS 频率 | 60.000Hz(晶振) | **60.03Hz**(= VMAX 2300 × 1H 7.242µs = 16.658ms) |
| XVS 低脉宽 | 7.25µs | 7.242µs(1H, XVSLNG=0) |
| STM32 PB10 | TIM2_CH3 输出 | 宣告期短暂输出(拉低50ms), 之后**输入捕获** |
| XHS | 无(死因) | cam0 自产, 相机间板上互连(138kHz, 1H) |
| 主从宣告 | 拉低 300ms + 500ms 等从机窗 | **拉低 50ms, 不等从机** |
| CYCLE | STM32 自产自数 | STM32 捕获线上下降沿计数(首沿=1) |

对齐引擎不受影响: CYCLE 仍在数据帧里、PA1 沿时间戳仍是锚点、
相机 PTS 与 XVS 同源(cam0 就是源)→ 标定后 offset 更稳。

## 双手方案(2026-09-04 定稿: TXS 隔断法)

问题: 从机手套的相机只能从 SBU 拿到 XVS、拿不到 XHS(XHS 网未过 SBU),
而从机相机启动必须 XVS+XHS 双信号 → 从机手套相机带不起来。

解法: **从机手套物理隔断 TXS0101(U18), 把相机侧与 STM32 侧两个 XVS 网切开**,
两边各自独立工作:

```
从机手套(隔断 U18 后):
  相机侧 1.8V 网(CSI0_XVS = P1.4+P2.4): 只剩两颗相机
        → 从机的 cam0 当 internal_master, 自产 XVS+XHS 锁自己的 cam1
        → 与主机手套内部完全相同的 dts / RV 固件 ✓
  STM32 侧 3.3V 网(IMU_FSYNC = PB10+SBU+IMU.FSYNC):
        → 主机手套的 XVS 经 SBU 送达, 从机 STM32 照常捕获计 CYCLE ✓
        → 两只手套 CYCLE 同源同号, 跨手套按 CYCLE 对齐成立 ✓
```

**隔断做法**:U18 的 OE(pin5)与 VCC 同接 VCC_1V8 网(焊死, 非 GPIO 可控),
故不能软件禁用。推荐**抬起 U18.5(OE)接地** → 芯片两端 Hi-Z, 效果等同拆除
且可恢复;或直接拆掉整颗 U18。

**代价(必须知道)**:从机手套的相机跟【本机】cam0 晶振、CYCLE 跟【主机】cam0
晶振 —— 两颗独立晶振差几 ppm → 相位每秒漂几 µs、累积不封顶。故:
- `align.c` 已升级为**滑动窗跟踪版**(锁定后持续用窗内残差中位数微调 offset),
  离线仿真 ±5/±20ppm、30 分钟零错拍;同源时中位数≈0, 主机手套零副作用;
- 残留物理事实: 从机相机做不到主机那种 −6µs 硬锁, 每隔几十分钟会有一次
  帧/周期滑移(某 CYCLE 对应 0 帧或 2 帧), pairs.csv 的 residual 列如实记录,
  后处理可识别。**这是本方案的天花板。**

**待实测**:主机侧 XVS 现在是 cam0 → TXS → SBU 线缆(~百 pF)→ 从机 PB10,
驱动力比原来 STM32 推挽直驱弱。理论上够(下降沿 FET 直通、上升沿 one-shot),
但接上线缆后**示波器看一眼从机 PB10 的边沿**, 软了再议。

**根治**:下版板把 XHS 也走 Type-C 的 SBU2(现在空着) → 四颗相机全部硬锁
主机 cam0, 漂移与滑移从根上消失。见 [BOARD_V5_CHANGELIST.md](BOARD_V5_CHANGELIST.md) P0-2。
## 其他注意

- STM32 侧 50ms 宣告期间相机尚未启动, XVS 网空闲, 无驱动冲突;
  宣告结束**必须先切输入捕获、再发 0xC301**(保证 cam0 起振时 PB10 已是输入)。
- 主机手套的 IMU FSYNC 也挂在同一 3.3V 网上, 两侧 IMU 都能收到主机 XVS
  → 将来 IMU 采样可硬件对齐到 XVS(V4 的意外收获)。
