# SCM1611 触觉传感器 UART 通信协议规范

> 整理自 `myDoc/SCM1611.pdf`（赛感科技 SYCSENSE，6 页）。
> 本文档作为 Glove_DAQ_G473 固件中 6 路 UART 解包代码的依据。
>
> 标记说明：✅ = 数据手册明确给出；⚠️ = 推断/需抓真实帧确认。

---

## 0. 角色与系统关系（重要）

- SCM1611 在协议里是「**设备 / 采集器**」（被动应答方）。
- 协议里的「**上位机**」= 主动发命令、收数据的一方。
- 在本项目中，**STM32G473 对 SCM1611 而言就是「上位机」**：STM32 发 `0x0011` 开始采集、接收 `0x0012` 数据流。
- STM32 收齐 6 路触觉 + 21 路 ADC 后，再作为 **SPI 从机**把数据发给真正的 PC 上位机。

```
  PC ──SPI──> STM32G473 ──6×UART──> 6× SCM1611（每个16路压力点）
 (真上位机)   (对SCM1611是上位机)        (设备/采集器)
```

## 1. 物理层 ✅

| 项目 | 值 |
|------|-----|
| 接口 | UART，TTL 电平 |
| 波特率 | **230400** |
| 数据位/校验/停止位 | ⚠️ 手册未明示，按惯例 **8-N-1**（需确认） |
| 供电 VCC-IN | 3.0 ~ 5.5 V（典型 3.3V），TTL 电平 3.3~5V |
| 工作电流 | 典型 5 mA，最大 20 mA |
| 帧默认间隔 | **10 ms（≈100 Hz）**，可通过 `0x009A` 查询 |

**接口定义（4P 0.8mm 连接器，型号 HCZZ0536-4）：**

| 引脚 | 名称 | 方向（相对 SCM1611） | 说明 |
|------|------|------|------|
| 1 | GND | - | 地 |
| 2 | VCC-IN | 输入 | 供电 3~5.5V |
| 3 | RX | 输入 | 接 STM32 的 **TX** |
| 4 | TX | 输出 | 接 STM32 的 **RX** |

> 接线：STM32_UARTx_TX → SCM1611_RX(3)；STM32_UARTx_RX ← SCM1611_TX(4)。

传感器侧：18P 0.5mm FPC 连接器，接 16 路电容式压力点 `电容_C0 ~ 电容_C15`，量程 0~10nF。

## 2. 帧结构 ✅

协议采用**一问一答**方式，由「帧头」+「有效负荷」两部分组成。所有多字节字段为**大端序（高字节在前）**（由示例帧推断，见 §5）。

| 偏移 | 字段 | 长度 | 说明 |
|------|------|------|------|
| 0 | 帧头 (magic) | 4 | 固定 `FF FF 06 09` |
| 4 | 帧序列号 | 2 | 每发一帧自动 +1 |
| 6 | 帧长 | 2 | **有效负荷长度** = 从「设备ID」到「数据」结束的字节数 |
| 8 | 设备ID | 4 | 主动发数据方的自有 ID。采集器=镜像唯一ID；上位机=IPv4 地址(Uint32) |
| 12 | 目标ID | 4 | 接收方 ID。设备发现/广播时为 `0xFFFFFFFF` |
| 16 | 命令字 | 2 | 见 §3 |
| 18 | 状态字 | 2 | 含义随命令字而变，见 §3 |
| 20 | 数据 | 变长 | 有效负荷，见 §4 |

- **整帧总长** = 8（帧头+序号+帧长字段）+ 帧长值。
- 当无数据时，帧长固定 = `0x000C`（12 = 4+4+2+2），整帧 = 20 字节。
- ⚠️ **本协议无 CRC / 校验和**。完整性依赖 magic number + 帧长定界。建议固件侧用 magic 同步 + 帧长一致性校验。

## 3. 命令字表 ✅

| 命令字 | 含义 | 方向 | 状态字语义 | 数据段 |
|--------|------|------|-----------|--------|
| `0x0011` | 数据采集开始命令 (Syc-data-start) | 上位机→设备 | `0x0000`=组播返回；`0x0001`=单播返回 | 空（帧长固定 12） |
| `0x0012` | 数据采集开始命令**回复** | 设备→上位机 | = **N**（返回的数据/触点个数）；`0x0000`=失败 | **N 个数据，每个 L 字节**（原始电容值 pF）见 §4 |
| `0x0013` | 数据采集停止命令 (Syc-data-stop) | 上位机→设备 | 空 | 空（帧长固定 12） |
| `0x0014` | 数据采集停止命令**回复** | 设备→上位机 | `0x0001`=成功；`0x0000`=失败 | 空（帧长固定 12） |
| `0x0099` | 帧速度(采集间隔)查询命令 (Syc-Frame-Rate) | 上位机→设备 | 空 | 空（帧长固定 12） |
| `0x009A` | 帧速度查询命令**回复** | 设备→上位机 | = **J 毫秒值**（设备默认 10ms） | 空（帧长固定 12） |

> ⚠️ 注意状态字「成功值」不统一：`0x0014` 用 `0x0001`=成功；`0x0011` 的 `0x0001` 表示单播。解析时务必按命令字区分，不要统一判 0/1。

## 4. `0x0012` 数据段解析（核心）

- 状态字 = **N** = 本帧返回的数据点个数（= 触点通道数，正常应为 **16**）。
- 数据段 = **N 个数据，每个 L 字节**，依次对应通道 0..N-1。
- 每个数据 = 该通道传感器的**原始电容值，单位 pF**。

⚠️ **待确认（唯一关键模糊点）**：手册原文写「返回 **2L\*N** 字节个数据，每个数据 L 个字节数」。
- 「每个数据 L 字节」明确；总字节最可能是 **L×N**。
- L 的具体数值未给出，最可能 **L = 2（uint16）** → 16 通道时数据段 = 32 字节，整帧 = 20 + 32 = **52 字节**。
- 数据值的字节序（大端/小端）未明示，**暂按大端**，需抓真实帧验证。
- **验证方法**：开采后抓一帧，读「帧长」字段值 = 12 + 数据字节数；用 (帧长−12)/N 反推 L，并比对状态字 N 是否为 16。

整帧布局（假设 L=2, N=16）：
```
FF FF 06 09 | seq(2) | 00 2C | devID(4) | targetID(4) | 00 12 | 00 10 | D0_hi D0_lo ... D15_hi D15_lo
                       └帧长=0x2C=44=12+32      状态字N=0x10=16    └─ 16 × uint16 电容值(pF) ─┘
```

## 5. 应用示例（手册原文）✅

开启数据采集，向 SCM1611 发送（hex）：
```
FF FF 06 09 00 00 00 0C 12 34 56 78 FF FF FF FF 00 11 00 01
```
逐字段解析：

| 字段 | 值 | 含义 |
|------|-----|------|
| 帧头 | `FF FF 06 09` | magic |
| 帧序列号 | `00 00` | 0 |
| 帧长 | `00 0C` | 12（无数据） |
| 设备ID | `12 34 56 78` | 上位机(STM32)自定 ID |
| 目标ID | `FF FF FF FF` | 广播/设备发现 |
| 命令字 | `00 11` | 数据采集开始 |
| 状态字 | `00 01` | 单播返回 |

整帧 20 字节。此示例证明多字节字段为**大端序**（帧长 `00 0C`=12、命令字 `00 11`）。

## 6. 典型采集时序

```
STM32 ──[0x0011 start]──────────────> SCM1611
STM32 <─[0x0012 data, N=16, 16×pF]──── SCM1611   ┐
STM32 <─[0x0012 data ...]──────────── SCM1611   ├ 每 ~10ms 一帧 (100Hz)
STM32 <─[0x0012 data ...]──────────── SCM1611   ┘
STM32 ──[0x0013 stop]───────────────> SCM1611
STM32 <─[0x0014 stop reply, ok=1]──── SCM1611
（可选）STM32 ──[0x0099]──> / <──[0x009A J=10ms]── 查询帧率
```

固件建议：每路 UART 用 `HAL_UARTEx_ReceiveToIdle_DMA`（空闲中断 + DMA）收变长帧；以 `FF FF 06 09` 做帧同步，按帧长截取，校验命令字=`0x0012` 后解析 N 个通道。

## 7. 待确认清单（建议抓真实帧/问厂商）

1. ⚠️ **L（每通道字节数）= ? 与数据字节序**（大端/小端）。最可能 L=2 大端，需实测。
2. ⚠️ UART 帧格式是否为 8-N-1。
3. ⚠️ 原始电容值(pF)到「压力」的换算关系/标定方式（手册未给，可能需厂商提供或自标定）。
4. ⚠️ 上电后是否需要先做「设备发现」(targetID=0xFFFFFFFF) 才能拿到设备真实 ID，还是可直接广播开采。
5. ⚠️ N 是否恒为 16，还是可能因某些通道失效而变化（解析时应以状态字 N 为准，不要写死 16）。
