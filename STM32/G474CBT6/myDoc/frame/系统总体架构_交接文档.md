## 0. 一句话总览

每只手套 = RV1126B（双相机 + SPI 主机）+ STM32G474（传感器主控 + SPI 从机）。
**主手套的 STM32 晶振是全系统唯一时基**：它产生 60.000Hz 的 XVS，相机、
从手套、5 路 CAN 节点、IMU 全部锚定在这个节拍上；每个节拍采一轮全量传感器
数据，装进 2690 字节的 SPI 帧，由 RV 取走与视频配对。

```
                 ┌─────────────── 手套 A（主）───────────────┐
   上位机 ◄──USB──┤ RV1126B ◄─SPI(2690B@60Hz)─ STM32G474      │
                 │  ├─ 双 IMX415（XVS 从机）    ├─ 5 路 CAN FD │
                 │  └─ 按键                     ├─ IMU(I2C)   │
                 └──────────────────┬───────────┴─────────────┘
                              XVS 线（互连 Type-C 的 SBU 芯，开漏线与）
                 ┌──────────────────┴────────── 手套 B（从）──┐
                 │  同构：STM32 输入捕获跟号，其余完全一样      │
                 └──────────────────────────────────────────┘
```

## 1. 时间基准（一切设计的地基）

- **XVS**：PB10 = TIM2_CH3（AF 开漏）。主机输出比较 toggle 产生波形：
  低脉宽 **10µs**（IMX415 规格 7.2~15µs，1H=7.242µs），周期 16667/16667/16666µs
  三拍抖动 → 平均**精确 60.000Hz**。**下降沿 = 同步沿**（开漏唯一的主动沿，
  IMX415 也是下降沿触发）。边沿由硬件在 CCR3 精确时刻产生，零抖动；
  中断只负责把 CCR3 前推（TIM2 中断 = 全系统最高优先级 0，另有迟到防护兜底，
  `pulse_late_cnt` 可观测）。
- **XVS 常开**：主机一旦放号就持续到"重新自检"——相机是同步从机，
  停号=失锁，重锁无帧数保证。开采/停采**不碰 XVS**。
- **CYCLE 同源 + 帧数一致（2026-09-02 第四次修订）**：相机在握手后才启动
  （STM32 发 0xC301 请 RV 启动，RV 回 0xC101），主机等两边相机都就绪再放
  第一个脉冲 → 该下降沿 = 双方 CYCLE 1 = 两边相机第一帧。**周期号与相机
  帧数从源头一致**，上位机直接按 CYCLE 对号。所有线上信令都发生在相机
  启动之前 → 绝无假帧。单手 = 握手窗口 500ms 超时直接走。
- **全局时间戳**：TIM2 32 位自由跑 @1MHz（1µs），71.6 分钟回绕，
  uint32 减法跨回绕天然正确。从机用输入捕获硬件锁存每个同步沿的时刻。
- **周期号 CYCLE** = 放号以来的连续节拍数（暂停期间照涨，Run 起点清零）→
  与相机帧号的偏移从锁相起恒定，跨段配对不需重对齐；跨手套直接按号对齐。
- **LED（PB2 排针外接）**：亮=自检完成等按键；灭=节拍已通等开采；
  RUNNING 每 180 拍翻转（两手套同相位闪=肉眼同步自证）。⚠ PB1 在 XVS
  网上，永远保持输入。

## 2. 系统生命周期（glove_fsm，状态图详见 glove_fsm.h 头注释）

```
上电 → SELFTEST：装通信测试包(0xAA01) → CAN 挂载检测（发 12 拍 SYNC 数回帧）
       + IMU 在位 + PD 电压 ADC → 装自检包(0x5401，bit=1 异常/缺席)
     （LED 亮的条件 = STM32 自检完 + 收到 RV 的 0x5501，RV 只测相机 I2C）
     → ROLE_WAIT：XVS 低>100ms = 对面是主机 → 从机路径
                  收到"是主机"(0x5101，唯一一次按键) → 回"收到" →
                  随机监听 20~147ms（竞态保险：监听期线被拉低 → 改判从机）
     → 主机：拉低 300ms 宣告 → 释放 → 500ms 窗口看从机是否拉低（超时=单手）
       从机：见宣告结束线回高 → 立刻拉低占线 + 发 0xC301 请 RV 启动相机
       两侧：RV 启动相机（从同步模式）→ 回 0xC101"相机就绪"
       从机：收到 0xC101 → 释放线 + 切输入捕获 → 进采集态等首沿
       主机：等 ①从机释放 ②自己 RV 回 0xC101 → +300ms 裕量 → 放 60Hz
             = 首沿 = 双方 CYCLE 1 = 直接 RUNNING（单手：收 0xC101 即放）
     → RUNNING ⇄ PAUSED（0xC201 停 / 0xC101 恢复，XVS 不停）
     任何时刻 0x5F01 = 重新自检（唯一停 XVS 的场合）
```

台架单手套调试：`GLOVE_FSM_AUTOSTART=1`（当前默认）自动走完主机流程，
上电约 3 秒直通 RUNNING。

## 3. 一个 60Hz 周期内发生什么（RUNNING 态）

```
t=0      XVS 下降沿（硬件精确）→ TIM2 中断（优先级 0）分发，顺序固定：
         ① canfd：SYNC(0x001) 压入 3 路原生 TX FIFO（~2µs/路）
         ② mcp2518：预装好的 SYNC 点火（写 1 个 TXREQ 位，~3µs/颗）
         ③ rv_link：PA1 拉低、冻结上周期缓冲、交换双缓冲、复位闸门/心跳
         ④ imu：置"该读 FIFO"标志
t~0.1..2ms  节点回帧 → 原生：RX 中断（优先级 1）直接解析写 send 缓冲；
            MCP：nINT→EXTI 置标志→主循环 SPI 读回
t=2.5ms  CAN 回帧窗口关闭 → 两个 CAN 生产者放行
t~3..5ms IMU I2C 批量读完成 → Mahony 积分 → 四元数/原始六轴写帧 → 放行
         三个生产者齐（或 8ms 超时）→ 封帧（CRC）→ 装 SPI DMA → PA1 拉高
t<16.7ms RV 读走 2690 字节；下个 XVS 重复
```

**生产者闸门**是这里的核心机制：节点回帧和 IMU 批量读的数据在语义上属于
"刚结束的周期"（采样时刻=同步沿），必须写进**刚冻结的 send 缓冲**、赶在
CRC 之前落地；缺席由心跳位表达，闸门超时兜底保证 SPI 链路永不停摆。

## 4. SPI 事务（方案 A，细节见协议契约 §1~§5）

- **恒定 1345 字（2690 字节）全双工**，任何阶段不变长。MISO：运行=数据帧，
  其余=小包占头 6 字+全 0；MOSI 前 6 字=可选命令小包。字 0 帧头分流。
- PA1 全阶段统一语义"高=有新包可读"；相邻事务 ≥100µs 间隔。
- CRC-16/ARC 软件查表（上电自检 "123456789"→0xBB3D），按线上字节序喂入。
- 数据帧：0x6A01 / 长度 1343（不含帧头不含自身含 CRC）/ CYCLE / 心跳 /
  关节 20×u32 / 触觉状态 5 / 触觉阵列 1280 / 六轴原始 6 / 磁力计 3 /
  四元数 Q14×4 / CRC。
- 小包表（含版本查询 0xE201→0xE301 回协议版本 1 + 固件 1.0）见契约 §4。

## 5. 传感器拓扑（编译期三选一：GLOVE_SENSOR_MODE）

| 模式 | 场景 | 总线使用 | 映射 |
|---|---|---|---|
| 0 | 正式手套 | 5 路 × 4 关节节点（0x101~0x104） | 槽 = bus×4+node-1 |
| 1（已废弃） | 误解产物，无对应硬件 | — | 保留仅作多节点拓扑参考 |
| **2（默认）** | 碳膜 ADC2CAN（即"转接板"） | bus0/1/2 = FPC1/FPC5/FPC4，回帧 0x201~0x203，三口顺序随意 | ADC1~20→槽 0~19；ADC21 丢弃（对 RV 与 20 关节方案零差异） |

三种模式下 SPI 帧布局对 RV **完全一致**，只是数据来源/语义随模式变。
模式 2 的触发帧就是现有 SYNC（板子不解析内容、三路去重）。

## 6. 模块地图（谁负责什么）

| 模块 | 职责 | 关键机制 |
|---|---|---|
| glove_protocol.h | 协议唯一真相源 | 帧布局/包表/拓扑宏/编译期断言，RV 可直接拷用 |
| glove_app | 唯一接线处 | 初始化顺序、XVS 分发链、主循环调度；main.c 永远只有 3 行 |
| glove_fsm | 系统状态机 | 自检/角色/启停、入站包分发、IMU 保活拍、暂存早到开采包 |
| rv_link | SPI 从机链路 | 双缓冲、生产者闸门、PA1、CTRL/DATA 内容切换、异常硬复位 |
| frame_sync | XVS 机构 | 主/从/强拉低/释放四态运行时切换、60.000Hz 抖动、迟到防护、看门狗 |
| canfd | 3 路原生 CAN | SYNC 广播、TDC、滤波、模式分支收帧、bus-off 自恢复 |
| mcp2518 | 2 颗 SPI 转 CAN | 寄存器级轮询驱动（勿改回 HAL，原因见其头注释）、预装载+点火、收发器 STBY |
| imu | ICM-45686 | 400Hz FIFO 批量读（全小端！）、Mahony 四元数、静止标定、I2C 卡死自愈 |
| glove_frame | 帧/包组装 | CRC、字段写入、小包 Build/Parse、验收假数据（RV_LINK_FAKE_DATA） |

## 7. 中断优先级表（2026-09-02 定稿）

| 优先级 | 中断 | 理由 |
|---|---|---|
| 0 | TIM2（XVS） | 10µs 脉宽窗口的保障；系统由 XVS 触发，此刻其余源安静 |
| 1 | FDCAN1/2/3 IT0 | RX FIFO 仅 3 深；500k/2M 下容忍 ~260µs，TIM2 只占 ~30µs |
| 2 | DMA、SPI1/2/3、EXTI3/15_10、I2C1 EV/ER、FDCAN IT1 | 均为短回调/错误处理 |
| 3 | TIM6（1kHz 看门狗） | 可被推迟 |

## 8. 可观测性（Live Expressions 全家桶）

`g_fsm`（状态/角色/自检位图/入站计数）、`g_sync_stats`（period 16666/16667
跳动=正常、pulse_late_cnt、alive）、`g_rv_stats`（帧计数/闸门超时/SPI 异常）、
`g_canfd`（每路每节点计数、a2c_seq_gap、错误）、`g_mcp`（SPI 自检/TEC）、
`g_imu`（acc_norm_g 静止≈1.0、标定进度、FIFO 水位）。
每种故障都有专属计数器，排障决策树见 CAN 交接文档 §6。
`RV_LINK_FAKE_DATA=1` = 全帧可校验假数据（RV 解析器回归测试用）。

## 9. 已知待办 / 边界

- 双手套从机全路径**未经实机验证**（代码就绪，等第二只手套）
- 触觉节点协议未定（帧内字段与 FIFO1 路由已预留）
- 磁力计桥接（IMU_MagBridgeInit 桩）、FSYNC 亚采样对齐（已关）
- 0xFD01 CAN 透传、节点管理帧（HELLO/SET_ID）、CAN bootloader
- 0xE101 LED 标定：V4 无 MCU 可控 LED，且锁相后偏移恒定可能已不需要
- PD ADC 阈值 500（2026-09-02 标定）；相机帧↔CYCLE 偏移的一次性标定方法待 RV 定
