# 致 RV 侧：启动流程重构（握手/帧数一致方案）—— 2026-09-02 第四次修订

> STM32 固件已实现。本文是对《协议契约_V1》的**增量变更说明**，供 RV 侧
> 代码实现。SPI 物理层、事务长度（恒定 2690 字节）、小包格式、数据帧布局
> **全部不变**；变的是启动流程、两个包的语义、一个新包。
> 本文**取代**上一版"CYCLE 同源方案"说明（那版已作废，勿参考）。

---

## 0. 一句话总结

相机启动挪到主从握手**之后**：STM32 用新增的 **0xC301 开采请求包**通知 RV
"现在启动相机"，RV 启动完毕回 0xC101。主机等两边相机都就绪后才放第一个
XVS 脉冲，**这个下降沿 = 双方 CYCLE 1 = 两边相机的第一帧** —— 两手套的
周期号和相机帧数从源头就完全一致，上位机直接按 CYCLE 对号。
全流程工人只按**一次**按键。

## 1. RV 侧要实现/修改的清单

### 1.1 上电自检瘦身（0x5501 语义变化）

上电后 RV **只自检相机 I2C**（探测传感器在不在、能否通信，**不启动相机、
不出流**）+ RV 自身其他自检，完成即发 0x5501。
- 0x5501 现在是 LED 亮灯（"可以按键了"）的必要条件：STM32 自检完 + 收到
  0x5501 才亮灯。**尽早发**。
- 收到 0x5F01（重新自检）后整个流程重来，**0x5501 需要重发**。

### 1.2 新增包：0xC301 开采请求（STM32 → RV）

| 字段 | 值 |
|---|---|
| 帧头 | 0xC301 |
| P0 | 本机角色：1 = 主机，2 = 从机 |
| P1 | 1 = 双手模式，0 = 单手模式 |

收到 0xC301 = **立即启动相机**：初始化到 IMX415 从同步模式（等 XVS，
不出帧），启动**完毕**后回 0xC101。
- 角色以 0xC301 的 P0 为准（之前的 0x5201"是从机"通知可能被 0xC301
  覆盖没读到，不影响流程）。
- 启动后到 XVS 到来只有**秒级**等待（不再有旧方案"几十秒无帧"的场景），
  但管线仍不得在这段时间超时。

### 1.3 0xC101 开采包语义变化

- **对 0xC301 的回执**："相机已启动就绪"。不再由工人第二次按键触发——
  **第二次按键取消了**，开采在握手链里自动开始。
- PAUSED 态下发 0xC101 = 恢复采集（这条不变）。

### 1.4 按键（只剩一次）

工人看到两手套 LED 都亮 → 按**任一只**手套的按键 → 该侧 RV 发 0x5101。
之后全自动直到出数据帧。按键去抖由 RV 负责。

### 1.5 采集开始的确认

RV 以"MISO 出现数据帧（帧头 0x6A01）"为采集已开始的最终确认。
主机侧：发 0xC101 后典型 300ms~1s 内出帧（等从机+裕量延时）；
从机侧：回 0xC101 后等主机放号，典型 1s 内出帧。
STM32 侧有 30s 超时（等不到 0xC101 或从机卡死 → 自动回自检，LED 灭→亮）。

## 2. 新版全流程（RV 视角，【RV】= 你要做的）

```
上电 → 【RV】自检相机 I2C + SD + 是否有USB外接设备等 → 发 0x5501
     STM32 自检(~0.3s) → 装 0x5401 自检包（PA1 高，【RV】读走可做 UI）
     → 双方自检齐 → LED 亮（等按键）
工人按任一手套按键
     → 【该侧 RV】发 0x5101 → 收 0x5301 → 等 0xC301（期间 STM32 在
        走宣告/握手，几百 ms）
     （对侧 STM32 自动判从 → 装 0x5201，【对侧 RV】读到可回 0x5301，
       同样等 0xC301）
STM32 握手完成（或 500ms 无从机 = 单手）→ 双方 STM32 各自发 0xC301
     → 【两侧 RV】启动相机（从同步模式，等 XVS 不出帧）→ 完毕回 0xC101
主机 STM32 等齐（从机释放线 + 自己 RV 回包）+300ms → 放第一个 XVS 脉冲
     ★ 第一个下降沿 = 双方 CYCLE 1 = 两边相机第一帧 ★
     → 两侧 MISO 变数据帧 → 【RV】开始收帧
     → LED 每 180 拍翻转（两手套同相位闪 = 同步正常的肉眼判据）
暂停：【RV】发 0xC201 → 回小包（XVS 不停）。恢复：发 0xC101。
任何时候【RV】发 0x5F01 = 重新自检全部重来（0x5501 记得重发）。
```

## 3. CYCLE / 帧数语义（定稿）

- 第一个 XVS 下降沿 = CYCLE 1（不是 0）；暂停期间 CYCLE 照涨（XVS 不停）；
- **两手套 CYCLE 同源同号**：上位机跨手套对齐直接 CYCLE 相等 = 同一时刻；
- **两边相机帧数一致**：相机都从第一个下降沿开始拍（IMX415 下降沿触发，
  握手信令期间相机未启动，绝无假帧）→ 相机帧 N ↔ CYCLE N 一一对应
  （RV 自己的帧计数起点若不从 1 起，做一次每手套的偏移标定即可）；
- 迟到/漏配的从机不会扰线（测不到 100ms 连续低），只会停在等待态
  （LED 常亮）——一只闪一只常亮 = 配对失败，发 0x5F01 重来。

## 4. 时序参数（glove_protocol.h，可协商改）

| 宏 | 值 | 含义 |
|---|---|---|
| GLOVE_XVS_CLAIM_MS | 300ms | 主机宣告拉低时长 |
| GLOVE_XVS_HANDSHAKE_MS | 500ms | 主机等从机拉低的窗口，超时=单手 |
| GLOVE_XVS_SLAVE_HOLD_MIN_MS | 100ms | 从机应答最短占线时长 |
| GLOVE_XVS_START_DELAY_MS | 300ms | 主机两条件齐后的放号裕量延时 |
| GLOVE_FSM_CAM_START_TIMEOUT_MS | 30s | STM32 等 0xC101 的超时（回自检） |
