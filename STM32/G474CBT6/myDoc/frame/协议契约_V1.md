# STM32 ↔ RV1126B 协议契约 V1（2026-09-02 第四次修订：握手/帧数一致方案、0xC301）

> 本文是 frame_note 方案评审后的**双方执行口径**，与固件实现一一对应。
> 固件侧唯一真相源：`Core/Inc/glove_protocol.h`（可直接拷给 RV 工程用）。
> 有冲突时以本文 + glove_protocol.h 为准，旧文档作废。

---

## 1. 物理层（不变）

SPI Mode 0，16bit/字，MSB first，硬件 NSS 低有效，一次 NSS = 一个完整事务。
线上字节序：每个 uint16 高字节先出；32 位量高字在前。
CRC-16/ARC（poly 0x8005 反射 / init 0 / 校验向量 "123456789"→0xBB3D），
按线上字节序喂入，小包覆盖 [0..4] 字，数据帧覆盖 [0..1343] 字（含帧头）。

## 2. PA1 握手 —— 全阶段统一语义

**高 = STM32 有一个新装载的出站包可读；低 = 没有。** RV 用上升沿触发读取。
- 小包被读走一次后 PA1 拉低，但**同一包保持可重复读**（CRC 恒有效），
  直到 STM32 装载新包再拉高。
- 运行态：XVS 同步沿 → PA1 低 → 数 ms 后（数据齐 / 8ms 超时）→ PA1 高。
- ⚠ PA1 上升沿相对 XVS 有毫秒级可变延迟，**不可用作视频对齐**；
  对齐用帧内周期号 ↔ 相机帧号。

## 3. 事务长度（方案 A：全程恒定，2026-09-02 定稿）

**任何阶段、任何方向，每次 SPI 事务都是 1345 字（2690 字节）**，不存在切换：

- **MISO**：运行态 = 数据帧（帧头 0x6A01）；其余状态 = 小包占开头 6 字 +
  全 0 填充。字 0 = 0x0000 不等于任何帧头，天然表示"没有新包"。
- **MOSI**：前 6 字 = 可选的 RV→STM32 小包（无命令填 0），其余填充。
  所以停采包可以直接搭在读数据帧的事务里发。
- RV 侧解析规则统一为：读 2690 字节 → 看字 0 的帧头 → 按帧头选小包（校验
  字 0~4 + 字 5 CRC）或数据帧（校验全帧 CRC）。
- **相邻两次事务之间留 ≥100µs 间隔**（STM32 重新装载 DMA 的窗口）。
- 将来的 CAN 发送包（0xFD01，变长内容）也装在这个固定事务里，
  内部自带条数上限，事务外壳长度不变。

## 4. 小包格式（6 字）

| 字 | 内容 |
|---|---|
| 0 | 帧头（下表） |
| 1 | 帧长 = 4（**不含帧头、不含自身、含 CRC** —— 与数据帧同一语义） |
| 2~4 | 载荷（无意义填 0xFFFF） |
| 5 | CRC-16/ARC 覆盖字 0~4 |

| 帧头 | 包 | 方向 | 载荷 |
|---|---|---|---|
| 0xAA01 | 通信测试包 | 从→主 | 3×0xFFFF |
| 0x5101 | 是主机 | 主→从 | 填充 |
| 0x5201 | 是从机 | 从→主 | 填充 |
| 0x5301 | 收到 | 双向 | 填充 |
| 0x5401 | STM32 自检包 | 从→主 | P0=在位图高16、P1=低16、P2=特殊状态 |
| 0x5501 | RV 自检完成包 | 主→从 | 填充。**RV 只自检相机 I2C 在位（不启动相机）+ RV 自身自检**，完成即发。重新自检(0x5F01)后需重发 |
| 0x5F01 | 重新自检包 | 主→从 | 填充 |
| 0xC101 | 开采包 | 主→从 | 填充。**语义（第四次修订）= 对 0xC301 的回执"相机已启动就绪"**；PAUSED 态 = 恢复采集 |
| 0xC201 | 停采包 | 主→从 | 填充 |
| **0xC301** | **开采请求包（新增）** | **从→主** | **STM32 请求 RV 启动相机（进 IMX415 从同步模式待 XVS），完毕回 0xC101。P0=本机角色(1=主/2=从)，P1=1 双手/0 单手** |
| 0xE101 | LED 标定包 | 主→从 | **预留暂缓**（V4 无 MCU 可控 LED，硬件确认前不实现） |
| 0xE201 | 版本查询包 | 主→从 | 填充（仅非运行态应答，RUNNING 中忽略） |
| 0xE301 | 版本应答包 | 从→主 | P0=协议版本(**=1**，即帧头低字节) / P1=固件主版本 / P2=固件次版本 |
| 0xFD01 | CAN 发送包 | 主→从 | **预留未实现** |

自检异常位图（2026-09-02 与 RV 统一：**bit=1 = 异常/缺席，与数据帧心跳同极性同布局**）：
bit0~19 关节（按帧内槽位）、20~24 触觉（未实现，恒1）、25 IMU、26 磁力计（未实现，恒1）、
bit27 = TYPE-C PD 高压缺失（VBUS 分压 ADC ≤ 500 判定）、bit28~31 恒 0。
注意：数据帧心跳的 bit27~31 维持保留恒 1，两包仅高 5 位的填充不同。
特殊状态 P2：bit0 = 主机握手窗口检测到从机（= 双手模式）。

## 5. 数据帧（1345 字 = 2690 字节）

| 字偏移 | 字节偏移 | 长度(字) | 字段 |
|---|---|---|---|
| 0 | 0 | 1 | 帧头 0x6A01 |
| 1 | 2 | 1 | 帧长 = **1343** |
| 2 | 4 | 2 | 周期号 uint32（高字在前），开机后随 XVS 递增，不清零 |
| 4 | 8 | 2 | 心跳位图 uint32（bit=1 本周期缺数据） |
| 6 | 12 | 40 | 关节 20×uint32（bit22:0 角度；缺席=0xFFFFFFFF） |
| 46 | 92 | 5 | 触觉状态 ×5 |
| 51 | 102 | 1280 | 触觉阵列 5×16×16 |
| 1331 | 2662 | 6 | **六轴原始 int16：ax ay az gx gy gz**（本周期最后一个样本） |
| 1337 | 2674 | 3 | **磁力计原始 int16 x y z**（桥接未启用=0 且心跳 bit26=1） |
| 1340 | 2680 | 4 | **四元数 int16 Q14：w x y z**（÷16384；未标定=16384,0,0,0） |
| 1344 | 2688 | 1 | CRC-16/ARC 覆盖字 0~1343 |

与旧版（2672 字节）差异：帧长语义改为不含自身（1335→1343）、
新增六轴原始+磁力计、总长 2690。**协议仍为 V1（未发布不升号）。**
量程换算：加速度 ±8g → 4096 LSB/g；陀螺 ±2000dps → 16.384 LSB/dps。

## 6. XVS 线（唯一的手套间通道）

两手套之间只有一条线（V4 网表证实，网名 IMU_FSYNC，3.3V 域）：
**PB10 + 互连 Type-C 的 SBU 芯（对侧 PB10）+ ICM-45686 的 FSYNC 脚 +
经 TXS0101 电平转换（内置上拉，即本线的上拉源）到 1.8V 给两个相机的
XVS 输入** —— 开漏线与。附带两个硬件红利：① IMU FSYNC 由硬件自动打标
（每个 XVS 下降沿），无需 GPIO 转发；② PB2（LED 网）与本线之间有 0Ω
预留位 R17，**必须不焊**（焊装则 PB2 只能作输入，LED 方案作废）。
该 Type-C 因两端均为 USB 主机而无法跑 USB 协议，仅 SBU 芯可用。

**波形（锁相后唯一允许的内容）**：
- 下降沿 = 同步沿；低脉宽 **10µs**（IMX415 合法 7.2~15µs，1H=7.242µs）
- 周期 16667/16667/16666µs 三拍抖动 → 平均**精确 60.000Hz**
  （单边沿偏离理想网格 ≤0.67µs ≪ 1H；period_us 在 16666/16667 间跳动是正常的）
- 主机上任后常开直到重新自检（唯一允许相机失锁的场合）

**握手信令（全部发生在相机启动之前 —— 相机在握手后才启动，绝不产生假帧；
IMX415 下降沿触发拍摄，释放的上升沿不触发）**：

| 信号 | 波形 | 谁发 | 谁收 |
|---|---|---|---|
| 主机上任宣告 | 持续低 300ms | 主机 | 从机（低 >100ms 即判"对面是主机"） |
| 从机应答+占线 | 见宣告结束（线回高）**立刻拉低并保持**，直到自己相机启动完（RV 回 0xC101）才释放；至少拉 100ms | 从机 | 主机（释放宣告后 500ms 窗口内低累计 ≥20ms 判"从机在"；窗口超时 = 单手模式） |

**启动流程**：握手判定后主/从各自向自己的 RV 发 **0xC301 开采请求** →
RV 启动相机（进从同步模式待 XVS）→ 回 0xC101"相机就绪"。
从机收到 0xC101 → 释放线 + 切输入捕获；
主机等 ①从机释放线（单手免）②自己 RV 回 0xC101，两者齐后再延
GLOVE_XVS_START_DELAY_MS(300ms 裕量) → 放第一个脉冲，**直接进入采集**。

**停采/恢复不走线**：0xC201 停采 → PAUSED（XVS 不停）；0xC101 恢复。

**XVS 常开原则**：主机一旦放号就持续 60Hz 直到重新自检（0x5F01）才停 ——
相机是同步从机，停号=失锁。放号后线上禁止任何信令，波形终身纯净。
**周期号 = 放号以来的连续节拍数**（暂停期间照涨），与相机帧号的偏移
从锁相起恒定，跨暂停段配对不需要重新对齐；段的管理（段号、起止）
由 RV/上位机侧记账，开采包载荷可携带段号（STM32 忽略该载荷）。

**周期号口径（2026-09-02 CYCLE 同源方案定稿）**：
1. **两手套 CYCLE 同源同号，可直接互比**。从机在释放线时已切好输入
   捕获，主机还要等 300ms 裕量才放号 → 主机第一个自产下降沿 = 从机
   第一个捕获沿 = 双方 CYCLE 1，此后数同一组物理沿。上位机跨手套
   直接按 CYCLE 对号。
2. **帧数一致**：相机在握手后才启动、两边都从第一个下降沿开始拍 →
   两边相机帧数天然一致，且与 CYCLE 一一对应。
   **迟到的从机不会扰线**：错过宣告的从机测不到 100ms 连续低（运行中的
   XVS 低脉宽仅 10µs），会一直停在等待态（LED 常亮）——工人看到一只闪
   一只常亮即知配对失败，对主机发 0x5F01 重来即可。
3. 相机帧↔CYCLE 的每手套一次性标定仍需要（RV 的帧计数起点是 RV 自己的），
   在 READY 之后做；放号起线上永无信令，偏移恒定，标定一次管全程。

## 7. 全流程（时序）

```
双方上电 → 各自 RV 上电自检：**只测相机 I2C 在位（不启动相机）+ 自身自检**
  → 完成即发 0x5501
双方 STM32 自检(~0.3s)：装 0xAA01 → CAN 挂载检测(12拍SYNC) → 装 0x5401
  → STM32 自检完 **且** 收到 0x5501 → **LED 亮**（等按键）
工人看到两手套 LED 都亮 → **按其中一个按键（全流程唯一一次按键）**
  → 该侧 RV 发 0x5101 → STM32 回 0x5301、LED 灭 → 随机监听 20~147ms
  （线被拉低→改判从机）→ 拉低 XVS 300ms（上任宣告）→ 释放
从机STM32 见线低>100ms → LED 灭、装 0x5201（RV 读到可回 0x5301）→ 等线回高
  → 回高瞬间**立刻拉低占住线** + 发 0xC301(P0=2 从机) 给自己的 RV
主机释放后 500ms 窗口内看到线被拉低（低累计≥20ms）= 从机在（双手模式）
  → 发 0xC301(P0=1, P1=1) 给自己的 RV
  （窗口超时 = 单手模式 → 发 0xC301(P0=1, P1=0)）
【两侧 RV 收到 0xC301】→ 启动相机（进 IMX415 从同步模式，等 XVS 不出帧）
  → 启动完毕回 0xC101"相机就绪"
从机STM32 收到 0xC101（且至少拉了 100ms）→ **释放线 + 切输入捕获**，
  进入采集态等第一个沿
主机STM32 等 ①线被从机释放 ②自己 RV 回 0xC101 → 两者齐后再延 300ms
  （从机理论上先就绪，纯裕量）→ **放第一个 XVS 脉冲 = 双方 CYCLE 1 =
  正式采集开始**（单手：收到 0xC101 立即放号）
  → 两侧 MISO 变数据帧，**LED 每 180 拍翻转**（3s 半周期；CYCLE 同号 →
  两灯完全同相位闪 = 肉眼同步自证）
暂停：RV 发 0xC201 → 切回小包，LED 灭。**XVS 全程不停**。恢复 = 发 0xC101。
容错：RV 以"MISO 出现数据帧"为采集开始的最终确认；等相机启动超时 30s
  （GLOVE_FSM_CAM_START_TIMEOUT_MS）STM32 自动回自检（LED 灭→亮 = 异常可见）。
任何时候发 0x5F01 = 重新自检（此时才停 XVS；RV 需重发 0x5501）。
```

**相机侧要求（比旧方案宽松）**：收到 0xC301 后才启动相机；启动后到 XVS
到来只有秒级等待（主机凑齐条件 + 300ms 裕量），不再有"几十秒无帧"场景。
相机从同步模式下第一个 XVS 下降沿开始出帧 → **两边相机帧数天然一致**。

## 7b. 自检假数据（RV_LINK_FAKE_DATA=1 时的验收向量，与 RV 文档 §6 逐字一致）

TACTILE 第 k 字（k=0..1279）= 自身字下标 = 51+k；
JOINT[i] = ((CYCLE & 0xFFF) + (i<<12)) & 0x7FFFFF；TAC_STAT[i] = 0xA500|i；
QUAT = {16384, 斜坡, 0, 0}；IMU_RAW[i] = 1000+i；MAG_RAW[i] = 2000+i；
HEARTBEAT：关节 0~3 与 IMU 位 = 0，另一位随 CYCLE 轮转，其余恒 1。

## 7c. 碳膜传感器模式（GLOVE_SENSOR_MODE=2，2026-09-02 新增）

固件编译期选择（glove_protocol.h 的 GLOVE_SENSOR_MODE，当前默认 2）：
0=正式手套（5 路×4 关节节点）；1=已废弃（误解产物，无对应硬件）；
2=碳膜 ADC2CAN 板（即"转接板"，3 路原生 CAN，21 路 12bit ADC）。

接线（已按 **V4 网表** myDoc/PCB/Netlist_Schematic1_1 复核，与 V2.1 相同）：
ADC2CAN 板的 3 个口接 **FPC1 / FPC4 / FPC5**（= FDCAN1/2/3 → FPC1/FPC5/FPC4），
三个口之间**顺序随意**（固件按帧内 group 字节重映射，接反只涨
a2c_group_mismatch 计数，数据不丢不乱）。
FPC2 / FPC3 是 MCP2518 路，当前模式 2 不解析，勿接。
FH64MA 7pin 针序：1/2=5V（VCC5V0_BUS）、3=CANL、4=CANH、5~9=GND/屏蔽。

模式 2 的 CAN 侧（ADC2CAN 协议 v1.0）：
- 触发 = 现有 SYNC（ID 0x001，板子不解析内容、三路去重）；
- 回帧 = 每路 16 字节 FD 帧：0x201/0x202/0x203，Byte0=seq、Byte1=group、
  Byte2..15 = 7×uint16 小端（0..4095）；固件按 group 字节映射（容忍接反）。

模式 2 对 SPI 数据帧的影响（**对 RV 零差异**，等同 20 关节方案）：
- 关节槽 0..19 = ADC 1..20 原始值（12bit，放 bit22:0）；
- **ADC21（group3 ch[6]）固件直接丢弃**（2026-09-02 定），触觉字段不占用，
  心跳 bit20~24 保持 1（缺席）—— RV 解析器完全不需要感知当前模式；
- 心跳 bit0..19 = ADC1..20 本周期新鲜；自检位图同布局。
观测：g_canfd.bus[x] 的 a2c_last_seq / a2c_seq_gap（板侧丢帧）/
a2c_group_mismatch（接线接反，数据已按 group 自动纠正）。

## 8. 固件侧调试开关（RV 未就绪时台架用）

`glove_fsm.h` 的 `GLOVE_FSM_AUTOSTART = 1`（当前默认）：STM32 不等 RV 的包，
自检完自动当主机（视同 0x5501/0xC101 已收到）、约 1.5 秒直通 RUNNING
持续出数据帧。RV 实现完整流程后置 0。
